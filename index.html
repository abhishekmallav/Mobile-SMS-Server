Why a local gateway

Put your phone plan
to work in development.

Test verification messages and server alerts with the Android device you already have. Start the server on your phone, then send requests from your development environment.

Use your existing SMS allowance
Messages are sent through your SIM rather than a paid cloud SMS API. Your mobile plan determines the cost.
Keep the API on your network
Your computer talks directly to the Flask server on your phone. No cloud SMS provider sits between your code and the device.
Bring your usual HTTP tools
Call the API from curl, Python requests, or Postman. Send a number and a message as JSON.

Working with the API

One request.
A message from your phone.

Open the app, tap Start Server, and use the WiFi IP address shown on the phone.

POST/api/sms

Provide number and message in the request body.

curl -X POST 'http://<PHONE_IP>:5000/api/sms' \
  -H 'Content-Type: application/json' \
  -d '{"number":"<RECIPIENT_NUMBER>","message":"<MESSAGE>"}'

Request template: replace the bracketed values before running. Check connectivity with GET /api/test.

See requests on the device

The Kivy interface displays the phone’s local IP address and HTTP request logs, so you can follow requests as you test.

Built on Android’s SMS APIs

PyJNIus bridges Python to SmsManager. The Flask server runs in a background thread with an Android notification.
